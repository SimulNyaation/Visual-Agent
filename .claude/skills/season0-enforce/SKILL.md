# 규칙 강제화 (Rule Enforcement)

규칙 강제화도 코드 변경이다. **명세 작성 → 승인 → `/season0-implement`** 절차를 따른다. 이 스킬은 명세 초안 작성까지만 수행한다.

## 절차

1. **교정 사항 확인**
   - `.season0/correction-log.md`에서 대상 항목을 확인하거나 신규 등록한다

2. **강제 수단 선정** (강제력이 높은 순으로 검토)

   | 수단 | 적용 조건 |
   |---|---|
   | API 설계 | 오용 경로 자체를 제거할 수 있을 때 (예: 상태 직접 할당 → 전이 함수만 공개) |
   | 타입 | 값의 종류로 구분 가능할 때 (예: 금액 전용 정수 타입) |
   | 모듈 경계 + import 제한 | 상호 참조를 금지해야 할 때 |
   | 린트 규칙 | 특정 API·패턴·주석 금지 |
   | 테스트 / 속성 기반 테스트 | 불변 조건으로 표현 가능할 때 |
   | 문서 (AGENTS.md) | 위 수단이 모두 불가능할 때만. 사유를 correction-log.md "검사 전환 불가 항목"에 기록 |

3. **기존 위반 조사**
   - 현재 코드베이스의 동일 패턴 발생 건수를 집계한다
   - 소량이면 이번 명세에서 함께 마이그레이션, 다량이면 베이스라인 동결 + 마이그레이션 계획 수립

4. **명세 작성** (`type: enforcement`)
   - 원문 요청: correction-log.md 항목과 Human의 교정 원문
   - 인수 기준 예:
     - "금지 패턴을 신규 작성하면 품질 게이트가 실패하고, 오류 메시지에 위반 사유와 권장 대안이 표시된다"
     - "기존 위반 N건은 베이스라인에 등록되어 있고 신규 위반은 0건이다" 또는 "기존 위반 N건이 모두 마이그레이션되었다"
   - 오류 메시지 초안 포함 (위반 사유 + 권장 대안 + 참조 예시 위치)
   - AI 가정 사항: 선정한 강제 수단과 대안

5. **제시 후 승인 대기**

## 완료 후

correction-log.md 해당 항목의 "전환 명세"에 명세 ID, "기존 위반 마이그레이션"에 진행 상태를 기재한다.
