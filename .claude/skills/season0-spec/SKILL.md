# 요구사항 명세화

원문 요청을 `.season0/specs/<ID>/spec.md`로 변환한다. **이 스킬은 구현하지 않으며 코드 파일을 변경하지 않는다.**

## 절차

1. **컨텍스트 수집 (읽기 전용)**
   - `.season0/config.md`: 도메인 구성, 모듈 경계
   - `.season0/feature-map.md`: 정식 명칭
   - `.season0/domains/`의 관련 도메인 프로필, `.season0/decisions/`
   - 관련 코드: 가정 사항의 근거 확보 목적으로만 열람

2. **명세 생성**
   - `.season0/specs/_TEMPLATE/spec.md`를 복제해 `SPEC-YYYYMMDD-slug/spec.md` 생성
   - `status: draft`

3. **항목 작성**

   | 항목 | 작성 규칙 |
   |---|---|
   | 0 원문 요청 | 요청자 원문을 **변경 없이** 인용 |
   | 1 목표 | 수단이 아닌 결과. 1~2문장 |
   | 2 인수 기준 | 코드 지식 없이 화면·산출물로 관찰 가능해야 함. "~하면 ~가 표시된다" 형식. 기능 맵 명칭 사용. 확인 방법에 Human 직접 확인 절차 포함 |
   | 3 범위 제외 | 에이전트가 확장하기 쉬운 인접 작업을 명시적으로 배제 (리팩터링, 디자인 변경, 타 기능 등) |
   | 4 용어 정의 | 명세 내 전문 용어별 1줄 정의 |
   | 5 AI 가정 사항 | 원문에 없으나 결정이 필요했던 모든 사항. 근거(파일 위치)와 대안 병기. 기술 선택(라이브러리, 저장 방식)과 동작 정책(기존 데이터 처리, 실패 시 동작) 모두 포함 |

4. **제시**
   - 명세 경로와 함께 **AI 가정 사항을 대화에도 요약** 제시 (최우선 검토 항목이므로)
   - "수정 사항을 알려 주시거나, 승인하시려면 `<ID> 승인`이라고 입력해 주세요"로 종료

## 금지 사항

- 이해도 검증, 퀴즈, 이해 여부 확인 질문을 하지 않는다. 이해도 검증은 Human의 책임 영역이다
- 가정 사항을 다른 항목에 섞어 기재하지 않는다
- 원문 요구사항을 임의로 확장·변경하지 않는다. 의문점은 가정 사항에 대안으로 남긴다
- `status`를 `approved`로 변경하지 않는다 (승인 문구를 받은 경우 제외, 아래 참조)

## 수정 요청 시

명세를 수정하고 승인 기록의 개정 이력에 1줄 추가한 뒤 재제시한다.

## 승인 시

Human이 대화에서 명시적으로 승인한 경우(`승인`, `approve`, `진행` 등 명확한 표현)에만:
- `status: approved`, `approved:` 일자, 승인 기록에 승인 문구 기재
- `/season0-implement` 절차로 진행
