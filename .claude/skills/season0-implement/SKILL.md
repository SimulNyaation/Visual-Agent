# 구현

## 착수 조건

- 대상 명세의 `status`가 `approved`인지 확인한다. 아니면 **구현하지 않고** Human에게 알린다
- `status: in-progress`로 변경한다

## 구현 규칙

1. **범위 준수**
   - 인수 기준(AC) 충족에 필요한 변경만 수행한다
   - 범위 제외(OOS) 대상은 변경하지 않는다
   - 범위 외 문제는 수정하지 않고 기록해 두었다가 검증 보고서 "범위 외 발견 사항"에 기재한다

2. **가정 사항 오류 시**
   - AI 가정 사항(AS)이 실제 코드와 다르면 **즉시 중단**한다
   - 명세를 수정하고 `status: draft`로 되돌린 뒤, 차이점을 Human에게 설명하고 재승인을 받는다
   - 임의로 방향을 바꿔 진행하지 않는다

3. **버그 수정 시**
   - 결함을 재현하는 회귀 테스트를 먼저 작성하고 변경 전 실패를 기록한다 (증적으로 사용)
   - 증상 회피(예외 무시, clamp 은폐, 타이머 대기, 조건 분기 우회)가 아닌 근본 원인을 수정한다
   - 동일 원인의 다른 발생 지점을 조사해 목록화한다 (범위 외면 범위 외 발견 사항으로)

4. **코드 품질**
   - `.season0/core/principles.md`, `.season0/config.md`의 모듈 경계, `.season0/domains/` 도메인 프로필의 안티패턴 금지 규칙을 따른다
   - 기존 코드에 안티패턴이 있어도 복제하지 않는다. 프로필의 권장 방식을 사용한다
   - 우회 코드를 정당화하는 주석을 작성하지 않는다. 설계 결정은 `.season0/decisions/`에 ADR로 남긴다
   - 신규 화면·영역은 `.season0/feature-map.md`에 등록한다
   - 상태 전이를 변경했으면 해당 상태 다이어그램을 갱신한다

5. **결정적 검사 추가 (해당 시)**
   - 이번 변경으로 유지해야 할 규칙이 생기고 결정적 검사로 표현 가능하면 구현한다
   - 오류 메시지에 **위반 사유 + 권장 대안**을 포함한다
   - 기존 위반이 많으면 베이스라인 동결 후 신규 위반만 차단한다

6. **완료**
   - `config.md`의 품질 게이트 명령을 실행해 통과시킨다. 실패를 무시하거나 검사를 비활성화하지 않는다
   - `status: verifying`으로 변경하고 `/season0-verify` 절차로 진행한다

## 금지 사항

- `approved`가 아닌 명세의 구현
- 품질 게이트 통과를 위한 규칙 완화 또는 베이스라인에 신규 위반 추가
- 명세에 없는 부수적 개선
