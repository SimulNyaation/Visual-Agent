# Domain Profile: web

## 적용 범위
브라우저 클라이언트와 서버 API로 구성된 웹 서비스. 교육 서비스의 기반 도메인.

## 모듈 경계

```
src/
  ui/          프레젠테이션 컴포넌트. 표시와 입력 처리만
  features/    기능 단위 모듈 (feed, order, course ...)
  domain/      비즈니스 규칙. UI·DB·프레임워크 비의존
  data/        API 클라이언트, DB 접근 계층
  server/      서버 전용 코드 (시크릿, 인가 처리)
```

| 경계 규칙 | 강제 수단 |
|---|---|
| `ui`는 `data`를 직접 참조하지 않음 (`features` 경유) | import 제한 린트 |
| `domain`은 `ui`, `data`, 프레임워크를 참조하지 않음 | import 제한 린트 |
| `server` 코드는 클라이언트 번들에 포함되지 않음 | 빌드 검사 / server-only 마킹 |

## 불변 조건
- 인증 필요 페이지는 비인증 상태에서 접근 불가
- 인가 판정은 서버에서만 수행 (클라이언트 UI 숨김은 보안 통제가 아님)
- 시크릿(API 키 등)은 클라이언트 코드에 노출되지 않음
- 동일 요청의 중복 제출이 데이터 정합성을 깨지 않음 (멱등성)

## 안티패턴 및 강제 수단

| 안티패턴 | 문제 | 강제 수단 |
|---|---|---|
| 컴포넌트 내 직접 fetch | 로딩·오류 처리 비일관, 재사용 불가 | `ui/` 내 fetch 금지 린트 |
| `useEffect` 기반 데이터 동기화 | 실행 순서 결함, 무한 루프 | 제품 코드 사용 금지, 데이터 훅으로 대체 |
| `any` 타입 | 타입 검사 무력화 | `no-explicit-any` 오류 처리 |
| `setTimeout` 기반 실행 순서 제어 | 타이밍 의존 결함, 환경별 동작 차이 | 사용 금지 린트 + 상태 기반 구조 안내 메시지 |
| API 경로 문자열 하드코딩 | 변경 시 다발적 장애 | API 클라이언트 단일화 |
| 우회 코드 정당화 주석 (`// 임시`) | 이후 에이전트의 복제 근거 | 특정 주석 패턴 금지 린트 |

## 상태 다이어그램 대상
- 인증 상태: 비인증 / 인증 / 세션 만료 / 정지
- 폼 제출: 입력 / 검증 실패 / 전송 중 / 성공 / 서버 오류

## 기능 맵 대상
- 페이지(라우트)별 정식 명칭
- 페이지 내 주요 영역 (헤더, 사이드바, 피드 패널 등)

## 권장 증적 형태
- 변경 전후 스크린샷 (모바일 뷰포트 포함)
- E2E 테스트 녹화 (Playwright 등)
- 네트워크 기록: 요청 횟수와 응답
- 접근성·성능 측정값 (해당 시)

## 타 도메인과의 관계
`social`, `delivery`, `learning`의 클라이언트·서버 코드는 모두 이 모듈 경계를 따릅니다.
