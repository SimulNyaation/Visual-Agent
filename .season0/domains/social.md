# Domain Profile: social

## 적용 범위
게시글, 댓글, 반응, 팔로우, 피드, 알림, 신고 등 **사용자 간 상호작용** 기능.

## 모듈 경계

```
features/social/
  posts/          게시글 CRUD
  feed/           노출 대상 조회 (읽기 전용)
  relations/      팔로우, 차단
  reactions/      좋아요, 댓글
  notifications/  알림
  moderation/     신고, 숨김, 제재
domain/social/
  visibility.ts   노출 권한 판정 단일 진입점
```

| 경계 규칙 | 강제 수단 |
|---|---|
| 공개 범위 판정은 `visibility` 단일 진입점에서만 수행 | 공개 범위 필드 직접 비교 금지 린트 |
| `feed`는 쓰기 작업을 수행하지 않음 | `feed` 내 쓰기 API import 금지 |

## 불변 조건
- 차단 관계의 사용자 콘텐츠는 피드·댓글·알림 어디에도 노출되지 않음 (양방향)
- 삭제·숨김 처리된 게시글은 모든 목록에서 제외됨
- 반응은 사용자당 1회. 중복 요청 시에도 카운트는 1만 변경 (멱등성)
- 표시 카운트(좋아요 수, 댓글 수)는 실제 레코드 수와 일치
- 비공개·제한 공개 게시글은 권한 없는 사용자에게 API 응답으로도 전달되지 않음

## 안티패턴 및 강제 수단

| 안티패턴 | 문제 | 강제 수단 |
|---|---|---|
| 목록별 공개 범위 조건 개별 구현 | 일부 누락 시 비공개 콘텐츠 노출 | `visibility` 강제 + 속성 기반 테스트 |
| 차단을 클라이언트에서만 필터링 | API로는 노출됨 | 서버 쿼리 계층 테스트 |
| 카운트 증감 연산 분산 | 정합성 누적 오차 | 불변 조건 테스트 (카운트 = 실제 수) |
| 기능별 알림 직접 생성 | 중복·누락 | 이벤트 기반 단일 알림 파이프라인 |

## 상태 다이어그램 대상
- 게시글 생애주기: 작성 중 → 게시 → (신고 → 숨김 / 복구) → 삭제
- 관계: 없음 ↔ 팔로우 ↔ 차단 (차단 시 팔로우 자동 해제)

## 기능 맵 대상
- 피드 유형 (전체, 팔로잉, 강좌별 등)
- 게시글 카드 내 액션 버튼 명칭

## 권장 증적 형태
- **다중 계정 시나리오**: 계정 A·B·C의 동일 화면을 병렬 캡처해 노출 여부 비교
- 공개 범위 × 관계 조합에 대한 속성 기반 테스트 결과

## 타 도메인과의 관계
`web` 기반. 교육 서비스에서는 수강 관계(`learning`)가 공개 범위 판정에 관여할 수 있으므로 해당 규칙도 `visibility`에 집중시킵니다.
