# ADR-003: 파일 작업은 코어가 하고, 덮어쓰지 않으며, 지울 때는 휴지통만 쓴다

- 일자: 2026-11-16
- 상태: Accepted
- 관련 명세: SPEC-20261116-file-explorer (AC6, AC15, AC21, AC23~AC27, AC35)

## Context
파일 칸에서 옮기기·복사·이름 바꾸기·지우기·새로 만들기를 한다. 명세의 목표는 "그 과정에서 기존 파일을 잃는 일은 없다"이다. 화면(웹)은 파일을 직접 만질 수 없고, 나중에 아이폰·노트북에서도 같은 화면을 쓴다. 에이전트가 같은 폴더의 파일을 동시에 바꿀 수 있으므로 "확인한 뒤 실행"하는 사이에 상황이 달라질 수 있다.

## Decision
- **파일 작업과 되돌리기 기록은 모두 코어에 둔다.** 화면은 프로젝트 폴더에서 시작하는 경로(`a/b/c`)만 보내고, 코어가 프로젝트 탭의 폴더를 기준으로 실제 위치를 정한다.
- **경로는 두 번 막는다.** 글자 단계에서 `..`, 드라이브 이름, 역슬래시, `.git`을 거절하고(`core/src/domain/file_rules.cpp`), 파일 시스템 단계에서 다른 곳을 가리키는 연결 폴더를 거치는 경로를 거절한다(`core/src/data/project_files.cpp`의 `locate`).
- **덮어쓰지 않는 Windows 함수만 쓴다.** 옮기기·이름 바꾸기는 `MoveFileExW(…, 0)`, 복사는 `CopyFileW(…, TRUE)`, 새 파일은 `CREATE_NEW`. 미리 확인한 뒤 그 사이에 같은 이름이 생겨도 Windows가 거절한다. `std::filesystem::rename`은 말없이 덮어쓰므로 쓰지 않는다.
- **여러 개를 옮길 때는 전부 아니면 전무다.** 먼저 모두 확인하고, 옮기다 하나가 실패하면 이미 옮긴 것을 되돌려 놓는다.
- **지우기는 Windows 휴지통(`IFileOperation`)으로만 한다.** 휴지통에 넣을 수 없어 바로 지워지려는 항목이 있으면 작업을 멈추고 지우지 않는다. 지운 것은 되돌리기 기록에 올리지 않는다.
- **되돌리기 기록은 프로젝트 탭마다 코어의 메모리에 쌓는다.** 옮기기·이름 바꾸기는 반대로 옮기고, 새로 만든 것·붙여넣은 사본은 휴지통으로 보낸다. 그 사이 파일이 없어졌거나 원래 자리가 차서 되돌릴 수 없는 작업은 기록에서 빼고 이유를 알린다(다음 Ctrl+Z가 그 전 작업으로 넘어가도록). 파일이 쓰이는 중이라 실패한 것은 기록에 남긴다.
- **밖에서 생긴 변화는 화면이 코어에 물어 두고 기다린다.** 화면이 "펼쳐 둔 폴더와 내가 아는 내용"을 보내면, 코어는 그 폴더들만 Windows 변경 알림으로 지켜보다가 달라진 폴더의 새 내용으로 답한다. 20초 동안 변화가 없으면 빈 답을 보내고 화면이 다시 묻는다. 새 요청이 오면 앞의 기다림은 끝낸다.
- **긴 복사가 다른 요청을 막지 않게** 파일 작업은 탭 상태와 다른 잠금을 쓴다.
- **자동 테스트는 실제 휴지통을 쓰지 않는다.** 환경 변수 `VA_TRASH_DIR`이 있으면 지운 것을 그 폴더로 옮긴다.

## Alternatives Considered
| 대안 | 장점 | 단점 | 기각 사유 |
|---|---|---|---|
| 되돌리기 기록을 화면에 둠 | 코어가 단순해짐 | 화면을 새로 고치면 사라지고, 원격 기기마다 기록이 달라짐 | 기록은 파일이 있는 PC에 하나만 있어야 함 |
| 지운 것도 Ctrl+Z로 휴지통에서 복원 | 한 가지 방법으로 모두 되돌림 | 휴지통에서 특정 항목을 찾아 꺼내는 과정이 실패 경우가 많고, 같은 이름이 여러 번 지워졌을 때 구분이 어려움 | 명세 AS1에서 제외 |
| 프로젝트 폴더 전체를 지켜봄 | 접힌 폴더의 변화도 즉시 앎 | `node_modules` 등 큰 폴더의 변화가 모두 전달되어 메모리와 처리량이 늚 | 명세 AS14 |
| 화면이 주기적으로 폴더를 다시 읽음 | 구현이 단순 | 변화가 없어도 계속 일하고, 화면 코드에 타이머가 필요함 | 타이머 금지 규칙(`.season0/config.md`) |
| 서버가 화면으로 계속 흘려보내는 방식(SSE) | 응답이 한 줄기로 이어짐 | 브라우저의 해당 기능은 요청에 접속 값 머리말을 붙일 수 없음 | 접속 값 확인 방식을 유지 |

## Consequences
- 앱을 닫으면 되돌리기 기록이 사라진다(명세 AS4).
- 한 번에 지켜볼 수 있는 폴더는 63개다. 그보다 많이 펼치면 넘는 폴더는 1초마다 다시 읽어 비교한다.
- 변화를 기다리는 요청은 한 번에 하나만 살아 있다. 원격 기기가 함께 접속하게 되면(SPEC-20261115-remote-access) 기기마다 따로 기다릴 수 있게 바꿔야 한다.
- 복사는 중간에 취소할 수 없다(명세 AS21).

## Enforcement
- 코어 코드가 덮어쓰거나 완전히 지우는 함수를 쓰지 않는지: `scripts/lint-core-files.mjs` (품질 게이트)
- 프로젝트 폴더 밖 경로 거절: `core/tests/file_rules_test.cpp`, `core/tests/project_files_test.cpp`(연결 폴더), `core/tests/file_routes_test.cpp`, `ui/e2e/files.e2e.mjs` ("AC27 …")
- 덮어쓰지 않음, 전부 아니면 전무: `core/tests/project_files_test.cpp` ("AC15 …", "AC26 …")
- 실제 Windows 휴지통: `core/tests/project_files_test.cpp`의 `recycle-bin-real` (돌릴 때마다 휴지통에 파일이 남으므로 품질 게이트 밖. `va_tests.exe -tc="recycle-bin-real*" --no-skip`)
- 휴지통에 넣을 수 없는 위치에서 지우지 않는지는 자동 검사 없음, 사유: 네트워크 드라이브 등 휴지통이 없는 저장 장치가 있어야 재현됨
