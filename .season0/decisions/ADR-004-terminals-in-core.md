# ADR-004: 셸은 코어가 Windows 가상 콘솔로 띄우고, 화면은 소식을 받아 가는 방식으로 그린다

- 일자: 2026-11-17
- 상태: Accepted
- 관련 명세: SPEC-20261116-terminal (AC5, AC7, AC10, AC11, AC16, AC17, AC21, AC28~AC30)

## Context
프로젝트 탭마다 터미널을 여러 개 띄우고, 그 안에서 에이전트(Claude Code 등)를 실행한다. 에이전트는 화면 전체를 쓰는 프로그램이라 색·커서 이동·키 입력이 실제 터미널과 똑같이 전달되어야 한다. 화면(웹)은 프로그램을 직접 실행할 수 없고, 나중에 아이폰·노트북에서도 같은 터미널을 봐야 한다. 코어 서버(cpp-httplib)는 양쪽에서 계속 주고받는 연결(WebSocket)을 지원하지 않는다.

## Decision
- **셸은 코어가 Windows 가상 콘솔(ConPTY)로 띄운다** (`core/src/data/pty.cpp`). 터미널마다 셸 하나, 그 출력을 읽는 스레드 하나를 둔다.
- **화면은 xterm.js로 그린다** (`ui/src/ui/xtermScreen.ts`, 명세 AS13). 터미널마다 글자 화면을 하나씩 만들어 두고, 작업 영역에 보이지 않는 동안에도 출력을 적어 둔다. 그래서 다른 터미널이나 다른 탭을 보다 돌아와도 내용이 그대로다.
- **출력은 화면이 "소식"을 받아 가는 요청 하나로 전달한다** (`POST /api/terminals/events`). 모든 터미널의 새 출력과 터미널 목록(이름, 실행 중인 에이전트)을 함께 답한다. 새 소식이 없으면 최대 20초 붙잡아 둔다. 파일 칸의 변화 기다리기(ADR-003)와 같은 방식이다.
  - 출력은 글자 중간에서 끊겨 올 수 있어 바이트 그대로(base64) 보낸다.
  - 한 번 받아 간 출력은 다시 주지 않는다. 받는 쪽은 한 번에 하나뿐이다.
  - 화면이 받아 가지 않은 출력이 4MB를 넘으면 셸의 출력을 잠시 붙잡아 둔다. 그래서 출력이 아무리 많아도 메모리가 끝없이 늘지 않는다.
- **입력은 요청으로 보내되, 화면이 한 번에 하나씩 차례로 보낸다** (`ui/src/features/terminals/terminalStore.ts`). 여러 요청이 동시에 가면 글자 순서가 뒤바뀔 수 있기 때문이다. 앞 요청이 끝나기 전에 쌓인 글자는 다음 요청 하나에 모아 보낸다.
- **닫을 때는 콘솔을 닫는다.** 그 콘솔에 붙어 돌던 셸과 프로그램은 Windows가 끝낸다. 터미널에서 띄운 창 있는 프로그램(편집기, 브라우저 등)은 콘솔에 붙어 있지 않으므로 끝나지 않는다.
  - 셸이 콘솔에 붙기도 전에 콘솔이 닫히면 Windows가 그 셸을 끝내 주지 않는다. 그래서 닫은 지 1초가 지나도 살아 있는 셸은 코어가 직접 끝낸다.
- **실행 중인 프로그램과 에이전트는 두 가지를 합쳐 알아낸다.** 하나는 작업 묶음(Job)이다. 셸을 작업 묶음에 넣어 두면 셸에서 실행된 프로그램이 그 묶음에 들어간다. 다른 하나는 "누가 누구를 띄웠는지"를 셸에서부터 따라 내려가는 것이다. Microsoft Store로 설치한 PowerShell 7은 Windows가 따로 관리해 그 안에서 실행한 프로그램이 작업 묶음에 들어오지 않기 때문에 둘 다 필요하다. Windows는 끝난 프로그램의 번호를 다시 쓰므로, 따라 내려갈 때는 띄운 쪽보다 나중에 시작한 프로그램만 받아들인다. 0.5초마다 그 목록의 실행 파일 이름(node로 도는 것은 명령줄까지)을 보고 에이전트인지 판단한다. 판단 규칙은 `core/src/domain/terminal_rules.cpp`에 있다. 작업 묶음은 알아내는 데만 쓰고, 끝내는 데는 쓰지 않는다.
- **닫기 전 확인은 코어가 판단한다.** 터미널·프로젝트 탭 닫기 요청은 실행 중인 프로그램이 있으면 `busy`로 거절되고, 화면이 확인 창을 띄운 뒤 `force`로 다시 요청한다. 앱 창 닫기는 창이 코어에 묻고(`ApiServer::requestClose`), 실행 중인 프로그램이 있으면 닫지 않고 화면에 확인 창을 띄우게 한다. 화면이 5초 넘게 소식을 받아 가지 않으면(화면이 멈춤) 확인 없이 닫는다. 닫을 방법이 없어지는 것을 막기 위함이다.
- **프로젝트 탭의 첫 터미널은 화면이 그 탭을 볼 때 요청하고, 코어가 "이번 실행에서 이미 띄워 준 탭"을 기억한다.** 그래서 보지 않은 탭의 셸은 켜지지 않고(명세 AS4), 마지막 터미널을 닫아도 저절로 다시 뜨지 않는다(AS6).
- **띄우는 셸은 PowerShell 7과 명령 프롬프트 둘뿐이고, 고르는 화면은 없다** (명세 원문 5). 터미널을 띄울 때마다 PowerShell 7을 먼저 시작해 보고, 설치되어 있지 않거나 시작에 실패하면 명령 프롬프트를 시작한다 (`core/src/data/terminals.cpp`의 `open`). 순서는 `core/src/domain/terminal_rules.cpp`의 `knownShells`에 있다.
- **자동 테스트는 셸을 숨길 수 있다.** 환경 변수 `VA_HIDE_SHELLS`에 적힌 셸은 없는 것으로 친다. 명령을 넣는 테스트는 PowerShell 7을 숨겨 명령 프롬프트를 쓴다 (PowerShell은 넣은 명령을 사용자의 명령 기록 파일에 남긴다).

## Alternatives Considered
| 대안 | 장점 | 단점 | 기각 사유 |
|---|---|---|---|
| WebSocket으로 주고받음 | 지연이 가장 짧고 구조가 흔함 | 코어 서버가 지원하지 않아 서버 부품을 바꾸거나 하나 더 넣어야 함 | 받아 가는 방식으로도 키 하나에 2~4ms, 10만 줄 출력에 10초로 충분함 (검증 보고서) |
| 앱 창(WebView2)의 전용 통로로 주고받음 | 서버를 거치지 않아 빠름 | 앱 창 안의 화면에서만 동작해 원격 기기에서 쓸 수 없음 | SPEC-20261115-remote-access |
| 닫을 때 작업 묶음을 통째로 끝냄 | 남는 프로그램이 확실히 없음 | 터미널에서 띄운 편집기·브라우저까지 함께 꺼짐 | 터미널을 닫았다고 사용자의 다른 프로그램이 꺼지면 안 됨 |
| 보이지 않는 터미널의 출력은 코어에만 쌓아 두고, 볼 때 다시 그림 | 화면 메모리가 줄어듦 | 크기가 다른 화면에 지난 출력을 다시 그리면 줄바꿈과 커서 위치가 어긋남 | 내용이 그대로여야 함 (AC16, AC20) |
| 에이전트를 터미널 출력의 글자로 알아봄 | 프로그램 목록을 볼 필요가 없음 | 에이전트가 화면 문구를 바꾸면 깨지고, 다른 프로그램의 출력에 속음 | 실행 파일 이름이 더 안정적임 |

## Consequences
- 앱을 닫으면 터미널도 모두 끝난다. 다시 켜도 이전 내용은 돌아오지 않는다(명세 AS2).
- 소식을 받아 가는 쪽은 한 번에 하나뿐이다. 원격 기기가 함께 접속하게 되면 기기마다 따로 받을 수 있게 바꿔야 한다 (ADR-003의 변화 기다리기와 같은 제약).
- 터미널이 떠 있는 동안에는 Windows가 그 프로젝트 폴더 자체를 지우거나 이름을 바꾸지 못하게 막는다(셸이 그 폴더에 자리 잡고 있기 때문). 폴더 안의 파일은 상관없다.
- 터미널에서 띄운 창 있는 프로그램은 "실행 중인 프로그램"으로 세어져 닫기 전에 확인을 묻지만, 닫아도 꺼지지는 않는다.
- 터미널 안에서 WSL을 실행하면, 그 안에서 도는 프로그램은 Windows에서 보이지 않아 에이전트인지 알 수 없다 (WSL 자체는 실행 중인 프로그램으로 센다).
- 알아보는 에이전트를 늘리려면 `core/src/domain/terminal_rules.cpp`의 `detectAgent`에 규칙을 더한다.

- 열쇠 없는 요청·다른 주소의 요청 거절: `core/tests/terminal_routes_test.cpp` ("… (AC30)"), `ui/e2e/terminal.e2e.mjs` ("AC30 …")
- 닫은 뒤 남는 셸·프로그램이 없음: `core/tests/terminals_test.cpp` ("… (AC29)" 세 가지), `ui/e2e/terminal.e2e.mjs` ("AC17 …", "AC28 AC29 …")
- Microsoft Store 설치본 PowerShell 7에서 실행한 프로그램도 알아봄: `core/tests/terminals_test.cpp` ("PowerShell 7에서 실행한 에이전트도 … (AC17, AC21)"). 실제 Claude Code·Codex로는 `ui/e2e/real-agents-check.mjs` (품질 게이트 밖)
- 출력이 끝없이 쌓이지 않음, 빠짐없이 차례대로 전달: `core/tests/terminals_test.cpp` ("… (AC11)" 두 가지)
