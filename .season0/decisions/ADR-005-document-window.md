# ADR-005: 문서 창은 코어가 읽어 준 글자를 화면이 그리고, 바뀜은 코어가 기다렸다 알려 준다

- 상태: 채택
- 날짜: 2026-11-18
- 관련 명세: SPEC-20261118-document-window

## Context
파일 칸에서 누른 파일을 앱 안에서 읽을 수 있어야 하고, 에이전트가 그 파일을 고치면 보고 있던 내용이 따라 바뀌어야 한다. 마크다운·머메이드·HTML은 그려서 보여 준다. 앱은 가벼워야 하고, 문서가 앱 화면을 바꾸거나 스크립트를 실행해서는 안 된다.

## Decision
- **파일 내용은 코어가 읽어 준다** (`POST /api/tabs/:id/files/read`, `core/src/data/project_files.cpp`의 `read`). 프로젝트 폴더 안의 글자 파일만, UTF-8로, 1MB까지 읽는다. 쓰기는 없다.
- **바뀜은 코어가 기다렸다 알려 준다.** 같은 요청에 `wait`을 주면, 화면이 알고 있는 것(내용의 stamp 또는 열 수 없는 이유)과 달라질 때까지 0.5초마다 다시 확인하며 최대 20초 붙잡아 둔다. 파일 칸(ADR-003), 터미널(ADR-004)과 같은 방식이다. 화면에는 타이머를 두지 않는다.
- **지켜보는 문서는 보고 있는 것 하나다.** 다른 문서를 지켜보기 시작하면 앞의 기다림은 코어가 바로 끝낸다. 가려진 문서는 문서 탭을 눌러 볼 때 다시 읽는다.
- **마크다운은 markdown-it으로 그린다** (`ui/src/ui/markdownView.ts`). 문서 안에 적힌 HTML 태그는 그리지 않는다(`html: false`). 그림은 설명 글자로 바꾼다. 링크는 눌러도 화면이 넘어가지 않게 막고, 프로젝트 안의 파일을 가리키면 문서 창에 연다.
- **머메이드는 mermaid로 그리되, 머메이드 그림이 든 문서를 처음 열 때 읽어 들인다** (동적 import). 문서 창을 쓰지 않으면 메모리를 쓰지 않는다. 보안 수준은 strict로 둔다.
- **HTML 문서는 `sandbox`를 비운 iframe에 그린다.** 스크립트가 실행되지 않고 앱 화면에 손댈 수 없다.
- **열어 둔 문서, 보던 문서 탭, 문서 경계의 위치는 화면이 기억한다** (앱이 켜져 있는 동안만). 개인 설정 파일의 형식은 바꾸지 않았다.

## Alternatives Considered
- 화면이 1초마다 다시 읽기: 화면 쪽 타이머 금지 규칙에 어긋남.
- 코어가 Windows의 파일 변경 알림으로 지켜보기: 파일 하나의 내용 변경까지 받으려면 폴더 지켜보기(ADR-003, 이름 변화만 받음)와 다른 길이 필요. 0.5초마다 날짜·크기만 확인하는 쪽이 단순하고 비용이 작다.
- 머메이드를 처음부터 함께 읽어 들이기: 쓰지 않을 때도 메모리를 씀.

## Consequences
- 앱 묶음이 약 8MB 커진다 (머메이드 부품. 읽어 들이기 전에는 메모리를 쓰지 않는다).
- 측정(2026-11-18): 문서 창 없이 107.5MB, 마크다운 문서를 열면 +5.0MB, 머메이드 그림을 그리면 +11.7MB.
- 날짜와 크기가 모두 같은 채 내용만 바뀐 파일은 바뀐 것을 알아채지 못한다 (드문 경우).
- 문서를 지켜보는 동안 코어의 요청 처리 자리 하나를 쓴다.
