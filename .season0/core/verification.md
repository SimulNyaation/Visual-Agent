# 검증 기준

## 증적 등급

| 등급 | 유형 | 예 |
|---|---|---|
| A | 자동 검사 결과 | 신규 테스트가 변경 전 실패 → 변경 후 통과한 기록 |
| A | 재현 가능한 실행 기록 | 시드·파라미터 고정 시뮬레이션 결과, 입력 리플레이 |
| B | 실행 화면 | 변경 전후 스크린샷, 조작 녹화 |
| B | 관측 데이터 | 로그, 네트워크 기록, 지표 그래프(개체 수, 프레임 타임) |
| C | 구조 다이어그램 | 상태 다이어그램, 흐름도 (코드와 대조 완료된 것) |
| — | 증적 불인정 | "확인했습니다", "정상 동작할 것입니다", 코드 발췌만 첨부 |

## 규칙

1. 인수 기준마다 **최소 1개** 증적. A등급이 가능하면 A등급 우선
2. 증적 파일은 `.season0/specs/<ID>/evidence/`에 저장하고 보고서에서 참조
3. 검증 불가 항목은 ⚪로 표기하고 **사유와 Human 직접 확인 절차**를 기재
4. 버그 수정은 **변경 전 실패 증적**을 포함
5. 판정 설명은 비기술 언어(Plain Language)로 작성. "테스트 통과" 대신 "신고된 게시글이 피드에서 제외되는지 검사하는 테스트 통과"

## 판정 표기

| 표기 | 의미 |
|---|---|
| ✅ | 충족 (증적 있음) |
| ❌ | 미충족 |
| ⚪ | 미검증 (사유 필수) |
